# Reflection: Lakehouse Anti-Patterns

In our LLM observability project, the team's data is most at risk of the **Small File Problem** (anti-pattern from slide §5). Given the ingestion rate of 1B requests per day, landing these logs as raw files without a proper compaction strategy would create millions of tiny objects (approx. 5KB each). This leads to massive metadata overhead in the Delta transaction log and cripples query performance due to inefficient I/O, making the 5-minute refresh SLA for Gold dashboards impossible to achieve.

Another significant risk is **Unpruned Scans** due to the lack of co-locality. Without clustering data by high-cardinality columns like `user_id` or `model`, every dashboard filter would trigger a full table scan.

To mitigate these, we utilized Delta's `OPTIMIZE` to compact small files into larger, more efficient Parquet blocks and applied `Z-ORDER` to co-locate related records. As demonstrated in the lab, this transition from 200 small files to a few optimized ones resulted in a >3x speedup, proving that active layout management is critical for maintaining a performant and cost-effective Lakehouse.
